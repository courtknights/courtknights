### TASK-002: Implement spec reference check

- **GitHub Issue:** [#52](https://github.com/courtknights/courtknights/issues/52)
- **Depends on:** TASK-001
- **Layer(s):** infra
- **Description:**
  Implement the spec reference check script and wire it into `infra/cicd/Makefile`:
  - Create `infra/cicd/check_spec_ref.sh`. The script reads two environment variables:
    - `PR_BODY` — the full text of the PR description.
    - `PR_LABELS` — comma-separated list of labels on the PR.
  - If `PR_LABELS` contains `no-spec`, exit 0 immediately.
  - If `PR_BODY` does not match `Spec: docs/specs/`, print an error message and exit 1.
  - Extract the spec path from the matched line and derive the spec directory.
  - Check that `<spec_dir>/05_acceptance.md` exists in the repository. If missing, exit 1.
  - Check that `05_acceptance.md` contains `Status: approved`. If not, exit 1.
  - Otherwise exit 0.
  - Update the `check-spec-ref` target in `infra/cicd/Makefile` to invoke the script.
- **Done when:**
  - [ ] `infra/cicd/check_spec_ref.sh` exists and is executable.
  - [ ] Script exits 0 when `PR_LABELS` contains `no-spec`, regardless of body content.
  - [ ] Script exits 1 when `PR_BODY` has no `Spec: docs/specs/` line.
  - [ ] Script exits 1 when the referenced spec has no `05_acceptance.md`.
  - [ ] Script exits 1 when `05_acceptance.md` exists but `Status:` is not `approved`.
  - [ ] Script exits 0 when `PR_BODY` contains a valid spec reference and acceptance is approved.
  - [ ] `make cicd-spec-ref` invokes the script with the expected environment variables.

### TASK-003: Implement backend coverage check

- **GitHub Issue:** [#53](https://github.com/courtknights/courtknights/issues/53)
- **Depends on:** TASK-001
- **Layer(s):** infra, api
- **Description:**
  Implement the backend per-layer coverage check script and wire it into `infra/cicd/Makefile`:
  - Create `infra/cicd/check_backend_coverage.sh`.
  - Phase 1 (unit): run `go test -coverprofile=coverage_unit.out -covermode=atomic ./...`
    from `api/`. Integration files are excluded automatically via the `//go:build integration` tag.
  - Phase 2 (integration): run `go test -tags=integration -coverprofile=coverage_int.out
    -covermode=atomic ./...` from `api/`. Testcontainers spins up PostgreSQL on demand.
  - For the API handlers layer, merge the two profiles into `coverage_api.out` by
    concatenating them and removing duplicate mode lines.
  - For each layer, filter the relevant coverage file by package prefix using `grep`,
    pipe to `go tool cover -func`, extract the `total:` percentage, and compare against
    the threshold defined in `docs/testing/strategy.md`.
  - On failure, print which layer failed, the actual percentage, and the required minimum.
    Exit 1.
  - Update the `check-backend-cov` target in `infra/cicd/Makefile` to invoke the script.
- **Done when:**
  - [ ] `infra/cicd/check_backend_coverage.sh` exists and is executable.
  - [ ] Script runs both unit and integration test phases.
  - [ ] Script computes coverage separately for all four layers.
  - [ ] Script exits 1 with a clear message if any layer is below its threshold.
  - [ ] Script exits 0 when all layers meet their thresholds.
  - [ ] `make cicd-backend-cov` invokes the script from the repository root.

### TASK-005: Implement ADR consistency check

- **GitHub Issue:** [#55](https://github.com/courtknights/courtknights/issues/55)
- **Depends on:** TASK-001
- **Layer(s):** infra
- **Description:**
  Implement the AI-assisted ADR consistency check script and wire it into `infra/cicd/Makefile`:
  - Create `infra/cicd/check_adr_consistency.py`.
  - Read environment variables: `PR_NUMBER`, `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`,
    `GITHUB_REPOSITORY` (e.g. `courtknights/courtknights`).
  - Fetch the PR diff via `gh pr diff $PR_NUMBER`.
  - Read all `docs/decisions/ADR-*.md` files from the current working directory (the checked-out
    PR branch).
  - Call `claude-sonnet-4-6` with the system prompt and user message defined in `02_architecture.md`.
  - Validate the JSON response schema; abort with a non-zero exit if the schema is invalid.
  - If `adr_files_modified` is non-empty: apply the `adr-change` label to the PR via the
    GitHub API.
  - If violations contain `BLOCKING` entries: post the formatted comment to the PR and exit 1.
  - If violations contain only `WARNING` entries: post the formatted comment and exit 0.
  - If no violations: exit 0 (no comment posted).
  - Update the `check-adr` target in `infra/cicd/Makefile`.
- **Done when:**
  - [ ] `infra/cicd/check_adr_consistency.py` exists.
  - [ ] Script reads ADR files from the current branch (not hardcoded paths).
  - [ ] Script validates the JSON response schema before acting on it.
  - [ ] `adr-change` label is applied when ADR files are modified.
  - [ ] PR comment is posted with the correct format on BLOCKING or WARNING violations.
  - [ ] Script exits 1 only on BLOCKING violations.
  - [ ] `make cicd-adr` invokes the script from the repository root.

### TASK-006: Create GitHub Actions workflow

- **GitHub Issue:** [#56](https://github.com/courtknights/courtknights/issues/56)
- **Depends on:** TASK-002, TASK-003, TASK-004, TASK-005
- **Layer(s):** infra
- **Description:**
  Create `.github/workflows/ci.yml` as a thin orchestrator that delegates all check logic
  to the `infra/cicd/Makefile` targets:
  - Trigger: `pull_request` targeting `main`, types `[opened, synchronize, reopened, labeled, unlabeled]`.
  - Concurrency: `group: ci-${{ github.event.pull_request.number }}`, `cancel-in-progress: true`.
  - Permissions: `pull-requests: write`, `contents: read`.
  - Four jobs running in parallel: `spec-ref`, `backend-cov`, `frontend-cov`, `adr-consistency`.
  - Each job checks out the PR branch, installs only the dependencies it needs, and runs its
    corresponding `make cicd-*` target.
  - `backend-cov` job uses `ubuntu-latest` with Docker available (required by Testcontainers).
  - `adr-consistency` job installs `anthropic` and `PyGithub` via `pip` and passes
    `ANTHROPIC_API_KEY` and `GITHUB_TOKEN` as environment variables.
  - Each job passes the required environment variables (e.g. `PR_BODY`, `PR_LABELS`,
    `PR_NUMBER`) extracted from the GitHub Actions event payload.
- **Done when:**
  - [ ] `.github/workflows/ci.yml` exists.
  - [ ] Workflow triggers on PR open, push, and label changes.
  - [ ] All four jobs run in parallel and each calls its `make cicd-*` target.
  - [ ] `backend-cov` job has Docker available (Testcontainers requirement).
  - [ ] `adr-consistency` job injects `ANTHROPIC_API_KEY` from repository secrets.
  - [ ] A PR to `main` without a spec reference fails the `spec-ref` job.
  - [ ] A PR to `main` with all checks passing shows four green status checks.
